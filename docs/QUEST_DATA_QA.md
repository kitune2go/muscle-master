# Quest Data Foundation QA

対象: PR #8 — クエストJSON定義・進捗評価器
基準日: 2026-08-15

## 自動検証

- `data/quests/core.json` がJSONとして読み込める
- `schemaVersion` と `packId` が存在する
- 全クエストIDが一意で、公開後に再利用しない形式になっている
- 全定義に `imageUrl`、`audioUrl`、既定トレーナー台詞の差し替え口がある
- デイリーは当日の記録だけを数える
- ウィークリーは月曜から日曜までを数える
- カテゴリ条件は種目カタログの複数カテゴリを評価できる
- 初回達成は同じクエストID・期間に対して一度だけ記録される
- 報酬受取台帳は同じクエストID・期間の二重記録を拒否する
- 旧保存データに `quests` がなくても空状態を補える
- Service Workerが評価器とJSONパックをオフラインキャッシュへ含める

## 回帰条件

- 保存キーは `muscleMasterStateV2` のまま
- セット完了1回あたりの基本XPは `+10 XP` のまま
- `days`、`totalSets`、4能力値をクエスト評価器から変更しない
- クエストJSONの取得失敗時も、セット完了・取消・タイマー・履歴を利用できる
- 画面レイアウトとキャラクター素材を変更しない

## このPRで表示されないもの

- ミッション一覧
- 報酬受取ボタン
- ボーナスXPの加算
- クエスト達成画像・音声・専用演出

これらは保存・評価基盤を確認した後、次PRでUIと接続します。そのためPR #8の目視確認では、既存画面が従来どおり動き、表示崩れがないことを合格条件とします。
