# Muscle Master — MASTER_SPEC 更新差分

更新日: 2026-08-15  
対象: `00_MASTER_SPEC_Muscle_Master v1.1` の §23.6「現在地」と §23.7「次の推奨作業」

この文書は、現行MASTER_SPECの機能要件を変更せず、GitHub実装の到達点と優先順位を更新するための差分です。内容が競合する場合は、本差分の記載を優先します。

## 1. 現在地

| フェーズ | 状態 | GitHub実装 |
|---|---|---|
| Phase 0: Foundation | 完了 | PWA、`localStorage`、曜日別メニュー、XP・レベル、テスト |
| Phase 1: Visual Design | 完了 | UIコンセプトシート準拠のGolden Screen、390px基準のレスポンシブUI |
| Phase 2: Character System | 基本完了 | トレーナー切替基盤、ユーザー名・トレーナー名編集、既存素材の差替え構造 |
| Phase 3: Training UX | 実行画面・タイマーまで完了 | 選択、セット進行、一時停止、回数種目の経過計測、時間種目のカウントダウン、フォーム説明 |
| Phase 4: Game Layer | 基盤実装 | JSONクエスト定義、進捗評価、初回達成記録、報酬受取台帳 |
| Phase 5: Records | 基本完了 | 直近履歴、累計セット、継続日数 |

## 2. PR #8で統合する範囲

- `data/quests/core.json` にデイリー3件、ウィークリー2件を安定IDで定義
- `quest-core.js` に日次・月曜始まり週次の期間計算と進捗評価を分離
- 既存の `days` と種目カテゴリから、セット数・実施日数を再計算
- `training:set-completed`、`training:set-reverted`、`training:day-reset` の内部イベントを追加
- 初回達成をクエストIDと期間の組合せで一度だけ保存
- 将来の報酬付与に使う重複防止台帳を追加
- JSONへ画像URL、音声URL、トレーナー台詞の差し替え口を追加
- JSONと評価器をPWAのオフラインキャッシュへ追加

今回の対象外:

- ミッション・報酬の画面表示
- ボーナスXP、称号、アイテムの実付与
- 画像、音声、宝箱、紙吹雪等の演出再生
- Gemini会話、音声応答、Live2D

## 3. 互換性の固定条件

- 保存キー `muscleMasterStateV2` を維持する
- 旧 `muscleMasterStateV1` からの移行を維持する
- セット完了1回あたり `+10 XP` を維持する
- ユーザー名・トレーナー名の編集と表示を維持する
- トレーナー切替基盤と既存キャラクター素材の参照先を変更しない
- 320〜430px幅で横方向のUI欠けを発生させない
- クエスト評価器は `days`、`totalSets`、`stats` を上書きしない
- クエストパックを取得できない場合も通常のトレーニング記録を継続できる

## 4. トレーニング実行画面

MASTER_SPEC §10.3に沿った「トレーニング実行画面」はPR #7で実装済みです。

1. 選択した種目名と回数・時間の固定表示
2. セット進行と一時停止
3. 時間種目用タイマー
4. フォームアドバイス
5. 完了後のXP・能力値フィードバック

キャラクター画像の最終差替えは、UIフローと表示領域が安定した後に行います。

PR #8では `docs/QUEST_ARCHITECTURE.md` に沿ってクエスト定義と進捗評価器の共通基盤を実装します。画面演出と報酬付与は、その基盤より先に実装しません。

## 5. クエスト拡張方針

今後は「トレーニング」と「クエスト」を次のように分離します。

- **トレーニング**：種目選択、セット実行、回数・時間、タイマー、完了記録
- **クエスト**：記録された行動の条件判定、進捗、達成、報酬、演出

クエスト画面は、将来的に `今日のメニュー` と `ミッション・報酬` の2領域を持つ構成とします。デイリー、ウィークリー、チャレンジ、イベント、隠し実績を同一の定義形式で追加できるデータ駆動方式を採用します。

実装順序は次のとおりです。

1. ~~トレーニング実行画面・タイマー~~ PR #7で完了
2. ~~クエスト定義と進捗判定の共通基盤~~ PR #8
3. **ミッション・報酬UI** — 次の推奨作業
4. 報酬の一度だけの付与と演出キュー
5. キャラクター反応、スタンプ、紙吹雪、宝箱、称号等の演出拡張

詳細設計は `docs/QUEST_ARCHITECTURE.md` を参照してください。
